## Model contract and independent reference values

For P05's fixed 1000-hour no-repair cooling mission, P06 follows three prospective FMEA rows
bottom-up: shared supply output absent (`S`), Pump A no-flow on demand (`A`), and Pump B no-flow on
demand (`B`). Each row maps item/function, example cause, local effect, next-higher effect, end
effect, observable effect, prevention control, detection control, and categorical consequence.
Effect columns use the row-under-analysis premise: only the named mode is present and all companion
items are available. Occurrence rows may co-occur, but combined-event effects return to P05's gate
logic rather than reusing a single-row effect unqualified.

Let `q_i` be the synthetic per-mission probability of mode `i`, and let
`c_i=P(indicator annunciates | mode i occurs)`. Conditional chain-rule accounting gives:

```text
detected_i = q_i*c_i
latent_i   = q_i*(1-c_i)
detected_i + latent_i = q_i
```

No independence assumption is needed for this partition. Failure-mode rows can co-occur, so
`sum(q_i)` is an expected affected-row count per mission, not the probability of a system union.
No RPN or ordinal-label multiplication is performed; P08 retains quantitative prioritization.

Independent Python reference arithmetic retained by focused tests:

- Baseline `q=[0.005,0.10,0.10]`, `c=[0.98,0.70,0.90]`: detected occurrence
  `[0.0049,0.0700,0.0900]`, latent occurrence `[0.0001,0.0300,0.0100]`, expected listed
  occurrence count `0.2050`, detected count `0.1649`, and latent count `0.0401` per mission.
- Pump-A occurrence sweep `qA=[0,0.05,0.10,0.20,0.40]` at `cA=0.70` gives expected listed
  counts `[0.1050,0.1550,0.2050,0.3050,0.5050]` and latent counts
  `[0.0101,0.0251,0.0401,0.0701,0.1301]`.
- Pump-A coverage sweep `cA=[0,0.25,0.50,0.70,1]` at `qA=0.10` holds expected physical count at
  `0.2050`, while detected count becomes `[0.0949,0.1199,0.1449,0.1649,0.1949]` and latent count
  becomes `[0.1101,0.0851,0.0601,0.0401,0.0101]`.
- Across both sweeps, the untouched shared-supply and Pump-B rows retain detected occurrence
  `[0.0049,0.0900]` and latent occurrence `[0.0001,0.0100]`; a Pump-A lever cannot redistribute
  observability between other FMEA rows while preserving only the aggregate totals.
- With all three `q` values one, the expected row count is three; this is valid as a count and
  demonstrates why it is not a probability.
- The broken log-only inventory is deliberately granted one oracle-filtered true-positive record per
  detected occurrence, perfect specificity, and unique mode attribution. At `qA=0.10,cA=0`, even
  that favorable inventory reports Pump-A occurrence zero while the physical and latent values remain
  `0.10`; its total expected-count underreport is `0.1101`. Raw logs can additionally overcount or
  misattribute modes, which this bounded counterexample does not model.
- At occurrence `1e-300` and coverage `0.5`, both partitions remain positive in independent Python
  arithmetic.

These values check the intended equations independently but do not prove MATLAB numerical fidelity.
